# VR 선거보도 시스템 v2 운영 안내

2026-11-24 기준. PC 가상 스튜디오를 중심으로 개발했으며, 실제 브라우저에서 WebGL 장면과 카메라 조작을 확인했습니다. 실제 사람의 편집 승인·실제 후보 공약 검수 완료·외부 공개 서비스 배포를 대신하는 문서는 아닙니다.

## 처음 실행

Windows에서 Python 3.12 이상을 설치한 뒤 프로젝트 루트의 PowerShell에서 실행합니다.

```powershell
./setup.ps1
```

필요 패키지 설치와 가상환경 생성 후 두 서버를 시작합니다. 다음부터는 `./start.ps1`을 사용합니다. 첫 실행에서 writer/editor 토큰을 각각 한 번 보여 줍니다. 작성자와 편집자는 서로 다른 담당자가 사용하며, 토큰을 입력한 뒤 **계정 확인**을 누릅니다. 토큰을 저장소나 공개 화면에 기록하지 않습니다.

- 업무 화면: http://127.0.0.1:8102
- PC 가상 스튜디오: http://127.0.0.1:8102/studio
- 보도 API 규격: http://127.0.0.1:8102/docs
- 종료: 시작한 터미널에서 Ctrl+C

기본 주소는 로컬 PC입니다. 원격 공유는 별도 HTTPS·사용자 관리·접근 제한·보존 정책을 정한 뒤 진행합니다. Docker 구성도 로컬 주소에만 포트를 연결합니다.

송신 서버의 기본 모드는 `hybrid`입니다. 원본 행까지 대조한 공식 최종 집계를 한 번 보내고, 별도의 시뮬레이션 이벤트를 계속 보냅니다. 보도 서버는 두 모드를 분리해서 조회합니다. 공식 파일이 동일하면 수집 시각이나 이벤트 순서가 달라도 같은 자료 ID로 인식해 검수 요청을 중복 생성하지 않습니다. 송신 서버가 잠시 없어도 보도 서버는 동일한 보존 원본으로 공식 자료를 확인할 수 있습니다.

## 공식 자료로 보도하기

1. **작업 자료**에서 2024년 공식 결과를 선택합니다. 14개 지역구·38명 후보를 불러옵니다. 기준시각·개표율은 원본 미제공이므로 비워 둡니다. 최종 집계를 가짜 중간 개표 이력으로 바꾸지 않습니다.
2. editor가 **자료·문서 검수**에서 원본 URL·집계·행 번호·합계와 정제 기준을 독립 대조합니다. 원본 CSV SHA-256 일치 검사는 자동 수행하지만 사람의 대조를 대신하지 않습니다.
3. writer가 지역과 후보를 선택한 뒤 **공약 문서 등록**에서 공식 원문 URL, 발행기관, 게시일, 이용 조건과 본문을 기록합니다. 선관위·국회도서관의 허용된 공식 도메인을 사용합니다.
4. 텍스트가 있는 PDF는 5MB·100쪽 이하에서 본문을 추출합니다. 원본 PDF와 해시를 보존하고 페이지 표시를 남깁니다. 이미지뿐인 스캔 PDF는 OCR 또는 직접 전사·원문 대조 후 본문을 입력합니다. OCR을 자동 완료했다고 표시하지 않습니다.
5. 등록자와 다른 editor가 문서를 독립 검수합니다. 검수 사유와 원문 확인을 남깁니다. writer의 등록 확인 체크는 독립 검수가 아닙니다.
6. writer가 초안을 생성합니다. 기사 문장마다 데이터 행 ID 또는 문서 근거 ID와 해시가 붙습니다. 공식 결과 기사에는 **공식 파일 집계·계산 득표율**을 명시합니다.
7. 규칙 검증을 실행합니다. 미검수 집계·문서, 수치·후보·지역·시각·원문 불일치와 근거 0건은 실패합니다. 실제 문장과 근거를 대조하고 수정본을 저장하면 새 ID로 다시 검증합니다.
8. 다른 editor가 원문 대조, AI 미연결 확인, 사유를 기록한 뒤 최종 승인합니다. 규칙 실패나 AI 판정 불일치는 사유만으로 우회 승인할 수 없습니다.

실제 후보 공약 본문과 독립 검수·기사 승인 기록은 사용자가 담당해야 합니다. 프로그램 설치만으로 확인되지 않은 실제 기사나 사람의 승인을 만들지 않습니다.

## PC 가상 스튜디오

Three.js 0.180.0과 OrbitControls를 로컬 파일로 포함했습니다. 실행 중 CDN 접속이 필요하지 않습니다. WebGL을 지원하는 브라우저와 하드웨어 가속이 필요합니다. 시작 실패 시 안내를 표시합니다.

- 마우스 드래그: 회전 / 휠: 확대 / 오른쪽 버튼: 이동
- 정면·좌측·우측·전체 버튼: 카메라 전환
- 자료·지역 선택: 3D 화면과 후보 막대 갱신
- 승인 기사 선택: 최신 재현 수치가 아닌 **기사에 고정한 수치** 표시
- 대본 읽기: 브라우저 음성 미리듣기. 영상 파일 음성에 자동 포함되지 않음
- 스튜디오 이미지 저장: 현재 3D 장면 PNG 다운로드
- 승인 철회 감지: 10초 간격으로 승인 목록을 확인하고 표시·읽기 중단

스튜디오 장면과 별도로 제작하는 MP4는 읽기 쉬운 FHD 뉴스 CG 영상입니다. 현재 MP4가 3D 화면을 직접 녹화한 파일이라고 주장하지 않습니다. HMD·WebXR 구현은 이 PC 중심 버전의 범위가 아닙니다.

## FHD 뉴스 제작

**뉴스 제작**을 펼치고 현재 모드의 승인 기사를 선택합니다. 기사당 5~120초, 전체 20분 이내로 설정합니다. 공식 자료와 시뮬레이션을 한 제작 묶음에 섞지 않습니다.

PCM WAV를 제공하면 영상에 결합합니다. 파일은 63MB 이하, 최대 20분이며 모노 또는 스테레오 PCM을 지원합니다. 직접 녹음/AI 합성 여부를 선택하면 CG·제작 원장에 표시됩니다. 음성을 제공하지 않으면 **음성 없음**으로 표시한 자막형 MP4를 생성합니다. 20분 음성은 16kHz 모노 PCM 등 제한 안의 형식을 사용하세요.

제작 상태는 대기 → 제작 중 → 완료 또는 실패입니다. 한 번에 하나씩 인코딩하며 대기 포함 4개까지 받습니다. 결과물은 실제 1920×1080, 25fps H.264 MP4와 SRT·대본·CG PNG·승인 JSON·원장·ZIP입니다. 긴 문장은 여러 CG로 나누며 모든 장면에 근거 ID를 연결합니다.

완료 파일을 내려받기 직전에도 승인과 원문 유효성을 다시 확인합니다. 근거·집계 검수가 철회되거나 승인 내용이 달라지면 오래된 파일은 다운로드할 수 없고 다시 제작해야 합니다. 서버 중단 중이던 제작 작업은 재시작 시 실패로 표시합니다. Linux에는 `fonts-nanum` 또는 `NEWS_FONT`로 지정한 한글 폰트가 필요합니다.

## 감사와 백업

editor의 **감사 이력**에서 행위자·시각·검증 실패·수정·승인·철회·제작 이력을 봅니다. 해시 연결 정상 여부를 확인하고 DB와 원문 ZIP을 내려받을 수 있습니다. 백업에는 users.json·토큰·제작 영상이 포함되지 않습니다.

복구는 서비스를 중지하고 기존 runtime/news를 별도 보존한 뒤 진행합니다. 백업의 news.sqlite, raw_documents, source_pdf를 같은 NEWS_DIR에 배치하고, 별도 보관한 사용자 파일을 복원하거나 새 토큰을 발급합니다. 운영용 계정·원본 데이터 파일·제작 영상은 별도로 백업합니다. 감사 기록은 일반 앱 경로의 수정·삭제를 막지만 관리자까지 막는 외부 WORM 저장소는 아닙니다.

## Docker 선택 구성

Docker를 사용하는 환경에서는 다음 순서로 실행합니다.

```sh
docker compose build
docker compose run --rm news python scripts/init_users.py --root /state/news
docker compose up -d
```

상태는 두 named volume에 보존하며 `docker compose down`으로 중지합니다. `down -v`는 데이터를 지우므로 복구 가능한 백업 없이 사용하지 않습니다. 이번 Windows 작업 환경에는 Docker 실행 도구가 없어 컨테이너 실행은 검증하지 않았습니다. Python 두 서버와 실제 브라우저·영상 인코더의 실행 결과를 제공했습니다.

## 검증 증빙과 범위

단위/API/실제 영상 56건, 두 서버 통합 13건, 전체 제작 통합 24건, 화면 로직 8건을 실행했습니다. TEST 계정의 가상 기사만 자동 승인했으며 실제 사람의 편집 승인이 아닙니다. 실제 3D 렌더링·카메라·문서 등록·초안·TEST 승인·영상 제작 완료를 브라우저에서 확인했습니다.

근거 검색은 선거·지역·후보로 제한한 문단 키워드 검색이며, 생성형 AI는 미연결입니다. 20개 팩트체크 기준 전체의 자동 의미 판단이나 임의 자유 문장의 정확성을 보장하지 않습니다. 문장 정형 검증과 사람이 하는 원문 검토를 함께 사용합니다.

## 04 기사 초안 생성

Windows `start.ps1`은 이 PC 전용 작성자 연결을 켭니다(`LOCAL_WRITER_ACCESS=1`). 02 영역에서 지역을 선택하고 04의 기사 초안 생성을 누르면 토큰 없이 `local-writer`로 연결해 초안을 저장합니다. 상태·오류·공약 근거 누락 안내는 04에 표시하고, 본문과 근거는 05에 표시합니다. 공식 공약이 미등록이면 개표 결과 문장만 작성하며 최종 승인을 우회하지 않습니다.

이 연결은 기본적으로 꺼져 있으며 루프백 접속·로컬 Host·동일 Origin POST만 허용합니다. 세션은 HttpOnly·SameSite=Strict 쿠키로 8시간 유지하며 서버 재시작 시 만료됩니다. 편집자·최종 승인 권한은 부여하지 않습니다. 외부 배포에서는 기존 담당자 토큰을 사용하세요.

## 관리자 로그인

`/admin/login`에서 관리자 아이디와 토큰을 입력합니다. 이 PC에서는 `admin` 아이디를 발급했고 토큰은 Git에서 제외된 `runtime/admin-access.txt`에 보관했습니다. 다른 설치에서는 `scripts/init_users.py --add-admin`으로 기존 계정을 유지하며 관리자만 추가합니다.

로그인 후 `/admin`에서 계정 목록을 확인하고 아이디·역할(작성자/편집자)을 지정해 새 토큰을 발급합니다. 기존 토큰은 조회되지 않으며 새 토큰은 한 번만 제공합니다. 로그아웃 시 세션은 서버에서도 폐기됩니다. 8시간 후 또는 서버 재시작 시 다시 로그인합니다. 로그인 실패 5회에는 5분 대기하며, 동일 Origin 요청과 HttpOnly·SameSite 쿠키를 사용합니다. HTTPS에서는 Secure 쿠키를 사용합니다. 관리자는 기사 작성·최종 승인 권한을 가지지 않습니다.

## 계정 관리 전체 흐름

1. `/admin/login`에서 관리자 인증 후 `/admin`으로 이동합니다. 기존 관리자 아이디와 토큰은 유지됩니다.
2. 담당자 이름, 로그인 아이디, 역할을 지정해 계정을 발급합니다. 토큰은 한 번만 표시되며 복사·보기·전달 완료 후 닫기를 지원합니다. 아이디와 역할은 변경하지 않아 기사 작성·승인 이력의 주체를 유지합니다.
3. `/login`에서 담당자 아이디와 토큰으로 로그인합니다. 작성자는 문서·기사 작성, 편집자는 독립 검수와 최종 승인을 담당합니다. 업무 화면에 계정과 역할을 표시하며, 담당자 세션은 업무 요청에도 적용됩니다.

계정 관리에서는 아이디·담당자 이름 검색, 역할·상태 필터, 활성 작성자·편집자 현황과 최근 로그인 시각을 제공합니다. 담당자 이름과 사용 상태를 수정할 수 있습니다. 사용 중지는 기존 세션과 API 토큰을 차단합니다. 재활성화 후 기존 토큰을 사용할 수 있으며, 재발급하면 기존 토큰과 세션은 만료됩니다. 토큰 재발급은 확인 창에서 확정합니다. 관리자 계정은 이 화면의 수정·중지·재발급 대상에서 보호합니다.

관리 이력은 계정 발급·상태 변경·토큰 재발급·로그인을 최근 100건 표시하며 인증 원문을 제외합니다. 관리자 권한과 작성/승인 권한은 분리되어 있습니다. 여러 담당자가 한 PC를 쓰면 로그아웃 후 다음 담당자가 로그인하세요. 역할을 나누는 기능은 실제 담당자의 원문 확인을 대신하지 않습니다.

[계정관리 실행 화면](../outputs/screenshots/account-management.jpg)은 별도의 TEST 계정과 시험 DB로 검증한 화면입니다. 실제 운영 계정을 임의 생성·중지·재발급하지 않았습니다. 새 계정 발급 → 작성자 세션 로그인 → 기사 생성 → 규칙 검증 → 다른 편집자 로그인 → 승인·내보내기를 자동 시험했으며, 사용 중지·재발급·로그아웃 후 기존 인증의 차단도 확인했습니다.

## 03 공약 근거 검색의 공식 자료

인천 14개 지역구 38명 후보의 선거공보 수록 위치를 국회도서관 공식 목차와 후보 데이터에 대조했습니다. 후보를 선택하면 공보 목차의 시작 쪽수, 발행연도, 발행기관, 소장기관, 수집시각과 공식 출처 링크가 표시됩니다. 정확한 게시일은 확인하지 못해 미제공으로 유지합니다.

- 공식 출처: https://dl.nanet.go.kr/detail/NONB12025000019286
- 정제 목차: `data/clean/campaign_directory.json`
- 출처 원장: `data/campaign_directory_ledger.json`
- 재수집 도구: `python scripts/collect_campaign_directory.py`

목차는 실제 공약 문장이나 이행 근거가 아닙니다. 공약 본문은 자동 수집하지 못했으며, 목차를 RAG 청크로 등록하거나 가상 공약으로 채우지 않습니다. 본문이 없으면 공약 근거 0건 상태를 그대로 유지하고 기사 검증·승인 차단을 유지합니다.

03의 ‘공약 원문 등록’에서 현재 선택한 지역·후보에 맞춰 공식 URL·게시일·본문을 등록합니다. ‘전체 근거 보기’는 검색어 없이 등록된 문단을 표시합니다. 검색 결과에는 실제 근거 ID와 독립 검수·반려·가상 자료 상태를 표시합니다. 한 번에 최대 5개 문단을 표시합니다.

2026-11-24 확인: 선관위 도서관 검색 양식은 HTTP 200을 반환했지만 결과 대신 안내 화면을 반환했습니다. 공약 본문을 확보했다고 기록하지 않았습니다. 보존한 목차 원본의 SHA-256과 후보별 쪽수 매핑을 검증하며, 검색어 불일치와 미등록 상태를 구분합니다.

## 관리자 토큰 실행 파일

프로젝트 루트의 `관리자_토큰_관리.cmd`를 더블클릭하면 기존 파일 열기(1), 재발급(2), 종료(0) 메뉴가 열립니다. 재발급은 `재발급` 입력 확인 후 실행하며 안내 파일은 메모장에서 열립니다. 토큰 원문은 콘솔에 출력하지 않습니다. 세션만 만료된 경우 토큰 재발급은 필요하지 않습니다. `python scripts/manage_admin_token.py --check`로 안내 파일과 현재 계정의 일치 여부만 확인할 수 있습니다.

## 로그인 화면의 관리자 토큰 재발급

1. `/admin/login`에서 ‘관리자 토큰을 잊으셨나요? · 토큰 재발급’을 누릅니다.
2. 관리자 아이디 `admin`과 본인 확인 방법을 선택합니다. 기존 관리자 토큰 또는 `runtime/news/admin-recovery.txt`의 `recovery:` 뒤 복구 코드를 입력합니다. 복구 코드는 서버의 로컬 시작 시 준비되며 웹에서 조회되지 않습니다.
3. 기존 토큰·세션 만료 확인에 체크한 뒤 ‘확인 후 새 토큰 발급’을 누릅니다.
4. 새 토큰을 복사·파일로 저장하거나 ‘새 토큰으로 로그인’을 누릅니다. `runtime/admin-access.txt`도 갱신되며 복구 코드는 새 코드로 바뀝니다.

재발급은 `LOCAL_WRITER_ACCESS=1`인 로컬 실행에서 루프백 접속·로컬 Host·동일 Origin 요청과 본인 확인을 통과해야 합니다. 기존 관리자 토큰/세션은 만료되며 작성자·편집자 계정은 유지됩니다. 확인 실패 5회 시 5분 대기합니다. 외부 접속·확인 누락·잘못된 코드로는 재발급할 수 없습니다. 새로운 토큰·복구 코드는 감사 기록과 GitHub에 저장하지 않습니다.

실제 브라우저에서는 재발급 창과 본인 확인 방법 전환을 확인했습니다. 실제 관리자 토큰은 시험 목적으로 재발급하지 않았으며, 기존 토큰·세션 만료와 복구 코드 교체는 별도 임시 DB의 자동 시험으로 검증했습니다.
